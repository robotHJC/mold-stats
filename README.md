# 模具车间表格统计器 · 界面设计说明

> 面向：示例五金制品有限公司这类**五金/模具厂**的生产计划统计。
> 形态：Windows 电脑为主，手机为辅的个人工具。
> 本文件是**界面设计稿的说明书**，配套原型 `web/index.html`（双击即可在浏览器打开，电脑/手机尺寸都能看）。

---

## 一、先看了你的真实文件，再设计

工作区里的 `2026年生产计划表) - 副本.xlsx` 是真实样本。我用 `tools/probe-sheets.js`
（纯手写 xlsx 解析，不依赖任何第三方库）扒开了它，结果如下：

| 事实 | 数字 |
|---|---|
| 文件大小 | **62.2 MB** |
| sheet 数 | **43 张** |
| 最大的表 | `2026年模具退客户改` 19.3 MB，`模具退维修` 5.3 MB |
| 有效数据行 | 约 **1.2 万行** |
| 真正的「主力表」 | 只有 **2 张**：`生产计划表`(1426 行×33 列)、`总计划表`(205 行×24 列) |

探查报告全文在 `tools/_probe/2026年生产计划表) - 副本.xlsx.txt`。

### 这些脏数据决定了界面长什么样

| 现象 | 真实例子 | 界面上的对应设计 |
|---|---|---|
| **表头不在第 1 行** | `总计划表` r1 是标题、r2 才是表头 | 「数据源」页专门有一块**表头探测示意** |
| **责任人行混在表头下** | `总计划表` r3 写的是「设计/设计/计划员/品质…」 | 必须排除，否则「设计」分组会多出一个叫「设计」的人 |
| **纵向合并单元格** | `客户名称`、`订单编号` 跨 N 行合并 | 自动向下填充 412 处，并在页面顶部**明确告知** |
| **日期是 Excel 序列号** | `46008` = 2025-12-17 | 自动还原 1834 格 |
| **日期列混文字** | `完成日期` 里写「待客户确认」「未拉模具」 | 校验页「日期列混进文字」12 处 |
| **一格塞多个值** | `生产班组` = `A/B/C`，`设计` = `黄/林/志/期/覃` | 筛选 **A/B/C 里查 B 也能命中**（代码里 `multi()` 做了拆分） |
| **列名重复** | `生产计划表` 有两个「设计」列 | 自动改名 `设计_2` |
| **列名带换行/空格** | `订单 编号`、`工序 名称` | 去空格后再匹配 |
| **一个格两个编号** | `261001/257011`（改模前后） | 校验项，去重计数会算错 |
| **WPS 嵌入图片列** | `=DISPIMG("ID_...",1)` | 统计时忽略 |
| **8 张空表/没改名的表** | `Sheet3`、`Sheet8`、`Sheet12`… | 自动跳过并折叠 |

### 一个很重要的发现

43 张表里，**有 17 张是同一套列骨架**（模具编号/零件名称/工序/工序名称/设计/生产班组）——
`送模`、`二次加工`、`26124`、`A`、`B`、`C`、`Sheet5`、`Sheet6`、`恒合打单`…

也就是说：**工厂的工作方式是「复制一张模板 sheet，每个订单/客户一张」**。
所以「全厂设计员工作量」这种统计，必须跨 sheet 合并才做得出来。

**这直接决定了界面的第一原则：不让你在 43 个名字里挑，而是按结构自动归堆。**

## 二、界面结构：4 个区

### 电脑端（≥900px）：左侧导航 + 主工作区

```
┌─────────────────────────────────────────────────────────────┐
│ ▦ 模具车间表格统计器   [文件胶囊]  v1.24  A− 100% A+  [换文件] │  ← 顶栏
├────────────┬────────────────────────────────────────────────┤
│ 数据源 43表│                                                │
│ 做统计     │                 主  工  作  区                   │
│ 结果       │                                                │
│ 校验 ✓38组 │                                                │
│            │                                                │
│ (底部说明) │                                                │
└────────────┴────────────────────────────────────────────────┘
```

顶栏右侧三样东西是「出问题时先看这里」：

- **`v1.24` 版本号** —— 看不到新功能先对一下这个号，对不上就是浏览器缓存（见第十节）
- **`A− 100% A+` 字号** —— 85% ~ 160%，表格/标题/按钮一起缩放，设置会记住
- **校验角标** —— 真的跑完对账才会显示（`✓ 38 组` / `差 2 组`），不是写死的数字

### 手机端（<900px）：单列 + 底部 4 个 Tab

底部 Tab 每个 `min-height: 56px`（拇指够得着），带红点数字角标提示待处理项。

## 三、四个区各自在干什么

### ① 数据源 —— 「我读到了什么」

1. **文件卡**：文件名 / 62.2MB / 43 个表 / 重点表 2 张
2. **绿色条「已自动处理」**：直接把做过的脏活列出来（表头定位 43 处、合并单元格填充 412 处、日期还原 1834 格…）——
   让你**敢信**这个工具，而不是怀疑它静默改了数据
3. **黄色条「需要注意」**：把会出错的地方提前说出来，带「一键校验」跳转
4. **两张主力表用高亮大卡**（`总计划表` / `生产计划表`），每张写清：
   - **一行代表什么**（一套模具 / 一道工序）
   - **这张表回答什么问题**（交期 / 现场执行）
   - 表头在第几行、有哪些坑
   - **全部列名铺开**，关键列高亮 —— 一眼知道能按什么统计
5. **另外 41 张表折叠归堆**，需要时再展开

### ② 做统计 —— 3 步，只做一件事：把记录按主列摊开

| 步 | 内容 | 设计要点 |
|---|---|---|
| 1 | **看哪张表** | **下拉选**（43 张表铺成列表要点半天）。每张表自己算自己的，不做跨表关联 |
| 2 | **以哪一列为主** | 任意一列。比如选「装配人」，结果就按装配人把人聚在一起 |
| 3 | **要统计哪些列** | 多选下拉，**选中的一定会出现在结果里**。点一下切换、全选 / 清空 / 反选，还能搜列名。**主列不在这份清单里** —— 它已经是分组标题了，再选一遍是多余 |

> 顶栏右侧有 **A− / A+** 字号调节（85% ~ 160%），表格、标题、按钮一起缩放。
> **手机上也能用** —— 窄屏时顶栏会换行、文件胶囊自己占一行，
> 不这样处理的话 `.fsctl` 上的 `overflow:hidden` 会把 `A+` 裁掉（看起来就是「只能减不能加」）。
> 字号和「上次填的」都会记住（浏览器本地），**换 sheet 各记各的，不会串**。

结果长这样 —— 一组一张卡，**默认全部收起**，点标题展开：

```
陈恩念                                     125 条
陈祖裕                                      72 条
黄德健                                      83 条
…（38 组，进来就是一页名单）

点开「陈恩念」后：
按什么细分 [装配完成时间 · 月份 ▾]   日期列按月份分 · 这一组共 125 条
装配完成时间 · 月份   1月 11  2月 8  3月 18  4月 15  5月 11  6月 10  7月 24 …
  ┌────┬──────────┬────────────┬──────────────┐
  │ ⇄  │ 模具编号  │ 零件名称    │ 装配完成时间  │
  ├────┼──────────┼────────────┼──────────────┤
  │拆 2 │ 2612483  │ 上门右拉杆… │ 2025-12-18   │
  │    │ 2612501  │ 底板        │ 2025-12-22   │
  └────┴──────────┴────────────┴──────────────┘
```

#### 细分筛选：某个人某个月做了多少

**「按什么细分」不在统计页，就在每一组的展开区域里** —— 展开哪一组、给哪一组选，
组与组之间互不影响（陈恩念按月份、黄德健按工序，各设各的）。

```
按什么细分 [— 加一个细分列 — ▾]  当前细分：装配完成时间 · 月份
date 列按月份分 · 这一组共 125 条

看某个值有多少条，点它一下就行 —— 下面的行会只留那些；再点一下取消。
装配完成时间 · 月份  1月11 2月8 3月18 4月15 5月11 6月10 7月24 8月20 9月8
                     ↺ 显示全部  − 移除细分
```

- 下拉里**只有你第 3 步勾了要统计的那几列** —— 不在那份清单里的列不给选，
  否则选一个屏幕上看不见的列来细分，人会懵；**日期列自动变成「· 月份」**
- 选完把该列从下拉里拿掉，并在旁边写一行 **「当前细分：XXX」** ——
  否则下拉一回位（回到「— 加一个细分列 —」）就没人记得刚才选的是哪一列
- 选完就出现一排可点的值，**每个值后面跟着它的条数**，数量加起来等于这一组的行数
- 点一下只看那个值，标题变成 **`8 / 125 条`**；再点一下取消
- 两个动作按钮用的是**大白话 + 中性配色**（不是红色）：
  **「↺ 显示全部」**（取消了筛选才会出现）和 **「− 移除细分」**。
  原来叫「清除」「× 去掉这层」并且是红的，看着像危险操作，没人知道是干什么的
- 可以叠加多个细分列（最多 3 个）；同一列里选多个 = 或，不同列之间 = 且
- 第 3 步勾的列全用上了，下拉会消失，改成提示「第 3 步勾的列都用上了」
- **导出的就是筛出来的**（所见即所得）

> 实测：陈恩念 125 条，按月份细分是
> `1月 11 · 2月 8 · 3月 18 · 4月 15 · 5月 11 · 6月 10 · 7月 24 · 8月 20 · 9月 8`，
> 加起来正好 125。点「3月」（18 条）→ 标题变 `18 / 125 条`，表里就是 18 行。

#### 一格多人：「赖学文/覃志坚」本来是两个人

主列里那种带斜杠的格子，**每一行都可以自己决定拆不拆**：

- 统计页上有个开关「一格多人：默认算两个人」（默认**开**），写在主列旁边 ——
  因为拆的就是主列那个值，它对人数的影响必须在选的时候就看得见
- 默认拆的情况下，`赖学文/覃志坚` 这一行会**同时出现在「赖学文」和「覃志坚」两个组下面**
  （行里显示的原文仍是 `赖学文/覃志坚`，一个字不改）
- 结果里这种行的行首有个小按钮 **`⇄ 拆 2` / `⇄ 不拆`**，点一下**只改这一条**的算法 ——
  因为同一列里「A/B」有时是两个人、有时就是一个名字里带斜杠，只有看数据的人分得清
- 改了默认开关，逐条的覆盖会全部清掉，回到统一口径

**数字会变，所以必须写在明面上**：副标题会写
`1424 条记录 · 38 组　其中 28 行是一格多人，拆开后共 1452 条计入分组`，
「这份结果是怎么来的」里也写清 `各组条数加起来是 1452 条，比 1424 行多 28 条 —— 那是拆出来的，不是重复`。
导出的表头同样写。**校验页用的是同一套拆分规则**，所以拆开不会被报成「重复添加」（见下）。

实测：`杨翠昭/陈恩念` 点「⇄ 拆 2」→ 陈恩念 125→**124**、杨翠昭 72→**71**，两个组同时少 1 条。

#### 三条硬规矩

1. **不去重。** 同一套模具挂多道工序就列多行；同一套模具被两个人做过，两个人下面各有一份。
   「谁做了多少套」看每行，「一共多少套」得回原始表数 —— 工具不替你合并。
2. **不汇总。** 没有合计行，也就没有「各行的去重数加起来 ≠ 全局去重数」这类错。
   屏幕上唯一的数字是「这一组有几条记录」。
3. **空缺就写「空缺」。** 不做填充、不做推测。空着的格子就是空着。

#### 带空缺的记录可以手动删掉

有空缺的那一行，行首有一个 **×**。点一下就把这条从**这次统计**里去掉：

- **所有数量立刻跟着变** —— 副标题的总条数、每组标题的「N 条」、组数、导出的行数，
  全都重新数一遍（删除是加在 `compute()` 的过滤那一层，不是各处去减一个数，所以不会对不上）
- 工具条里有 **「删掉所有带空缺的（N 条）」** 一次清掉，和 **「恢复已删除的」** 撤销
- 某个人如果所有记录都被删了，**这一组会整组消失**（组数也会从 45 变成 42）
- **不会改动你的 Excel 文件** —— 只是在这次统计里不算它们。界面上有一条黄条写明这一点，
  导出的表头里也写「手动删除：本次统计已排除 N 条（未改动原始文件）」
- 换一张表，删除记录自动清空

> **为什么把聚合整个拿掉**：先分组再聚合的报表里，去重数、平均、比率、最大最小
> **全都不可加**（一套模具被两个人做过，各行的去重数相加就多算一套）。
> 与其堆一堆「合计不可相信」的解释，不如默认不聚合 —— 需要汇总时导出到 Excel 自己加。

#### 默认什么都不预填，但会告诉你还差几步

进入「做统计」时，**主列和列都不替你选** —— 上一版是按列的填充率猜的，猜错了反而误导人
（猜出「设计延期」只有 87/1424 行有值，却排在默认统计项第一位）。现在：

- 主列下拉第一项是 `— 请选择以哪一列为主 —`，**没选之前结果页只会提示你回去选**
- 缺什么，就在「开始统计」上面用黄条列出来：`还差 2 步就能出结果：1. 第 2 步：选以哪一列为主…`
- 对应那张卡同时高亮描边，选完之后**提示立刻消失、高亮立刻撤销**（`renderNeeds()` 同时挂在
  `renderStat()` 和 `renderColPicker()` 上 —— 只挂在其中一个的话，选完列提示不消失，
  用户会以为没生效）
- 想一步到位就点**模板**：「按 装配人 看」「装配人 × 月份」两键配好主列 + 列 + 细分

#### 原表核对：回原表对一遍（独立重算）

每一组的标题右边有一个 **「原表核对」** 按钮。点开是一个只读弹层，把**源表原样画出来**，
左边是 **Excel 行号**、表头是 **列标（A / B / C…）**，跟你手上的 Excel 一格一格对得上。

**这个功能的意义全在「独立」两个字上 —— 它不复用统计结果。** 两边分别算：

| | 从哪来 | 里面有什么 |
|---|---|---|
| **甲面 · 统计结果** | `compute()` 之后的那批行 | 已经过了筛选、手动删除 |
| **乙面 · 原表重扫** | 直接回解析出来的原始行，按主列的值重新找一遍 | **不加任何筛选、不做去重、不删任何行** |

然后**只对「行号」做差集**，差集不为空就报出来：

- `原表里有 N 行属于这一组，但统计结果里没有 —— 漏了：11, 512, 880`
- `统计结果里有 N 行，回到原表却找不到 —— 多出来的：999999`
- `统计里同一条被算了 2 次 —— 重复添加，行号：11`
- `另有 N 行是你自己手动删掉的（不算漏）` ← 用 `__rid` 认出来，跟真遗漏分开算
- `这一组下面有细分筛选，界面上另外藏了 N 行` ← 那是你自己缩的范围，也不算漏

**验过它真的会报警**：手动往结果里塞一条重复行 → 立刻变 `❌ 对不上` 并指出行号 11；
塞一个不存在的行号 999999 → 报「多出来的：999999」。正常数据下是 `✅ 对上了`。

其它细节：

- 表体里 <span>黄底</span>＝算进这一组的，**红底**＝原表里属于这一组却没被统计到的
- 右上角一键切 **「显示整张表」**（黄底照旧标出来），用来扫「有没有整条被漏掉的人」
- 标题下面写清主列在**原表里是第几列**：`主列 装配人 在原表里是 R 列（原表从左数第 18 列）`
- 应用里算出来的列（`装配 延期(天)`、`装配 工期(天)`）标一个 **「算」** —— 原表里没有它，
  只能按行号对，不能按列标对
- 原表里没有表头的列（`第7列`）不进下拉也不画，但**列标照样跳号**（F 直接到 H）——
  界面上会写一句「原表里还有 1 列没有表头（G）没画出来，不是漏列」
- **只读**：整个应用里没有任何写回本地文件的 API（`showSaveFilePicker` / `createWritable`
  一个都没有），导出走的是 Blob 下载 —— 原文件一个字节都不会动

#### 老功能还在，只是先藏起来

时间分组（按天/周/月/季）、聚合统计项（列 × 算法）、筛选条件这三块，
代码**整套保留**，只是界面上收进了一个 `#advCards` 容器。
把 `web/index.html` 里的 `UI_SIMPLE` 改成 `false` 就全套回来 ——
包括 KPI 卡、排行图、交叉表、以及空值／不可加总的口径提醒。

### 时间粒度：按天 / 周 / 月 / 季度 / 年

（下面是老功能，当前被 `UI_SIMPLE` 屏蔽着，改回 `false` 即可使用。）

这是单独一个开关，不是普通分组列。选好**用哪一列当时间轴**（比如「装配完成时间」），
再点粒度按钮。界面会实时告诉你这一列能不能用：

> 「装配完成时间」有 **83** / 94 行能归期，其余（空值或写了文字）归到「未填」。

「未填」会单独成一列/一行 —— 因为工厂表里「没填完成日期」本身就是一个要追的结论，
不能默默丢掉。

开关时间维度后，交叉表会自动变成**行 × 月**的形状：

```
装配人 ＼ 月份 · 装配数量   1月  2月  3月  4月  未填   合计
刘寿明                       5    5    ·    2     0     12
张潮标                       5    ·    1    1     0      7
成凌平                       9    ·    1    1     0     11
…
```

### 一格多人：「李千军/黄德健」怎么算

真实文件里确实有这种格子（`2025项目汇总` 第 13 行）。所以第 2 步有一个开关：

> 表里有 **28** 行是一个格子写了多个人。勾选后两人各记一次（**默认**）；取消则只算第一个。

实测差异：同一份数据，拆开是 **92** 条装配量，只算第一人是 **81** 条。
这个开关直接影响工人计件/绩效的数字，所以放在明面上让你看得见、能切。

**「装配数量」的口径**：`装配完成时间` 已填的条数（不是所有工序条数）。
和「工序数」分开列，所以能看出「派了多少活 vs 干完了多少」。

### ③ 结果 —— 「直接告诉我结论」

- **一句话结论**（蓝色大卡）：`按【客户名称】看了 14 组、150 套模具，整体准交率 20%。最拖的是 宏昌（平均 45.7 天），最稳的是 莱伦（0 天）。`
- **4 个 KPI 卡**：行数 + 当前统计项前三名的合计值
- **三种视图**：明细表（主索引重复的行标红）· 排行条形图 · 交叉表
- **导出**：图片 / Excel / PDF / CSV。
- **口径说明**：用类 SQL 的样式把「取哪张表、主索引是什么、按什么分、算什么、筛了什么」全列出来 —— **可追溯**

### ④ 校验 —— 一键把所有组回原表对一遍

原来是 15 条**硬编码**规则（写死了「9 类问题、296 处」这种示例表上的结论）。
它有个要命的问题：**导入真文件后并不会真的跑** —— 它只是把示例表的结论印在屏幕上。
已经删掉了。

现在这个页签装的是真正的对账，就是上面那个「原表核对」的批量版：

- 点进去**自动把所有组跑一遍**，18 ms 跑完 38 组 / 1424 行（手机上也不卡）
- **结论写在最上面**：`✓ 全部 38 组都对上了 —— 回到原表重扫一遍，行号一个个都对得上，`
  `没有漏、没有多、没有重复。统计这边 1452 条 / 原表重扫 1452 条 · 扫了整张表 1424 行 ·`
  `主列 装配人 = R 列（原表从左数第 18 列）`
- 四个数字卡：**漏掉的 / 多出来的 / 重复添加 / 手动删除的**（0 就是好的）
- 对不上的组排在最前面，写出**具体是哪几行的行号**，右边一个「看原表」直接打开只读弹层
- 下面还有全部组的清单（`甲面 / 乙面` 两个数并排 + ✓ 或 ✕），一眼扫完
- 页签上的角标就是结论：`✓ 38 组` 或 `差 2 组`（不再是写死的 296）

**它不看统计时用的那份数据。** 甲面是统计给出的行号，乙面是拿着主列的值直接回
解析出来的原始行重新扫一遍 —— 不加筛选、不去重、不删行。两面做差集才有意义，
否则就是把同一份结果看两遍，什么问题都发现不了。

**一格多人的拆分用的也是同一套规则**，所以拆开不会被误报成「重复添加」。
「手动删除的」单独算，不算漏。

## 四、重点两张表的口径

> 下面两张是范例。现在**统计项不再写死**，而是「选一列 + 选怎么算」现场生成，
> 所以下表里列的指标都能这样拼出来：
>
> | 原来叫 | 现在这样选 |
> |---|---|
> | 装配套数 / 模具套数 | `模具编号`（或`订单编号`）· **去重数** |
> | 工序数 / 装配数量 | 任意列 · **条数** |
> | 设计延期合计 | `设计延期` · **合计** |
> | 平均装配工期 / 装配延期 | `工期(天)` / `延期(天)` · **平均**（派生列直接写在每一行里）|
> | 按时完工率 | 用条件筛 `延期(天) ≤ 0`，再 `延期(天)` · **条数** ÷ 总条数 |
>
> 跨列算的比率类（准时率这种）做不成单一列+算法 —— 用**条件**表达，
> 比编一个说不清楚的指标名更透明。

### 总计划表（订单级 · 205 行）—— 管**交期**

| 分组维度 | 时间列 | 可算指标 |
|---|---|---|
| 客户名称(12) · 设计(8) · 生产班组(3) · 模具类型(3) | 接单日期 · 计划交模日期 · 实际交模日期 | 订单数 · 模具套数 · **交模套数** · **平均延期天数** · **准交率** · 最长延期 · 未交模订单 · 平均交货周期 |

> 延期天数 = 实际交模日期 − 计划交模日期
> 准交率 = 延期 ≤ 0 的订单 ÷ 已交模订单

### 生产计划表（工序级 · 1426 行）—— 管**装配现场**

真实表里一个「模具编号」下挂多道工序，所以模具编号会重复出现。
结构是三层：**订单 → 模具 → 工序**，装配人是按模具定的（一个人负责整套模具的装配）。

| 分组维度 | 时间列（六选一当时间轴） | 可算指标 |
|---|---|---|
| 装配人(12) · 零件名称(19) · 客户名称(14) · 设计(8) · 生产班组(3) · 线割供应商(8) · 工序名称(17) | **装配开始时间（开工）** · **计划装配完成时间（截止）** · **装配完成时间（完工）** · **实际送样时间（送样）** · 图纸下发（出图） · 下单时间（下单） | **装配套数** · 装配数量 · **平均装配工期** · **装配延期** · **按时完工率** · 最长装配延期 · 送样完成数 · 工序数 · 图纸及时率 · 设计延期合计 |

> 最常用：`装配完成时间` **按月** × `装配人` → **每月每人的装配量**。
> 换成**按季度**/按周/按天，同一套配置直接重算。

### 「装配了多少」的两个口径

| 指标 | 算法 | 用在哪 |
|---|---|---|
| **装配套数** | `模具编号` 去重计数 | 报工作量、算工时 —— **一套模具多道工序只算一套** |
| 装配数量 | 工序条数 | 看细活，一套模具多道工序就算几条 |

两个都给，不替用户决定。

### 装配工期与延期（三个时间列的含义）

| 时间列 | 含义 | 算式 |
|---|---|---|
| 装配开始时间 | **开工** | — |
| 计划装配完成时间 | **截止** | `装配工期 = 完工 − 开工`（这个人花了几天） |
| 装配完成时间 | **完工** | `装配延期 = 完工 − 截止`（正数＝拖了，负数＝提前） |
| 实际送样时间 | **送样** | `按时完工率 = 完工 ≤ 截止 的比例` |

**没完工的行不算 0 天** —— 工期/延期只对已经完工的行取平均，否则会拉低平均值、
把“还在干”当成“干得快”。选“装配完成时间”当时间轴时，没完工的会单独归到「未填」。

### 某个人某段时间到底装配了多少

两步：

1. **第 4 步加一个日期区间** —— 日期列（如「装配开始时间」）的运算符自动变成 **介于 / 早于 / 晚于**，
   并带 **本月 / 上月 / 全年 / 清空** 快捷按钮。默认就给生产计划表挂了一个区间条件，但两挠为空＝不筛。
2. **点交叉表的行标签下钻** —— 点“成凌平”就把下面的明细表缩到他一个人，再点一下取消。

### 明细一定要能看到模具

汇总数字不够用，所以结果页专门有一块 **下钻明细表**，跟着数据源自动换列：

- 生产计划表：`模具编号 · 零件名称 · 物料编码 · 工序 · 工序名称 · 装配人 · 装配开始时间 · 计划装配完成时间 · 装配完成时间 · 实际送样时间 · 工期 · 延期`
- 总计划表：`订单编号 · 模具编号 · 客户名称 · 零件名称 · 模具套数 · 设计 · 生产班组 · 接单日期 · 计划交模日期 · 实际交模日期 · 交模延期`

延期 ≤ 0 不标、1–7 天标黄、> 7 天标红；未完工/未交模单独写清楚，不冒充 0 天。

### 导出范围：哪几组要发出去（定到组）

结果里每一组的标题上都有一个 **「导出」勾选框**，默认全勾。像这种就该去掉：

```
（装配人为空）   133 条   ← 主列是空的，本来就没有名字
李                1 条   ← 名字被截断了
莫守源            1 条
```

- **「（主列为空）」那一组默认就不勾** —— 它连名字都没有，发出去只会让人问「这是谁」
- 取消勾选后：整组变灰、虚线框，标题上多一个红色 **`不导出`** 标签
- 底部导出卡片里有一条汇总：`导出范围：36 / 38 组 · 1194 条（全量 1424 条）`
  `不导出：（装配人为空）（133）、陈恩念（125）`，带 **全选 / 全不选 / 只排除空主列** 三个快捷键
- 结果页工具条上也会写 `导出 36/38 组`

**它只影响导出，不动统计。** 屏幕上的条数、组数、各组明细、校验页的对账，全部照旧 ——
这是跟行上的 **×** 的关键区别：× 是「从这次统计里去掉」（所有数量跟着变），
这个勾是「统计里还看得见，只是别写进文件里」。两条路都有，各管各的事。

四种导出都认这个开关：

| 导出 | 怎么排除的 |
|---|---|
| Excel / CSV / 图片 | `S.last.rowsOut` 只装勾上的组，四种格式共用这一份数据 |
| PDF / 打印 | `@media print { .gr.noexp { display:none } }` —— 打印也是导出，不勾的不能出现在纸上 |

「这份结果是怎么来的」里也会写一行
`导出范围：已排除 2 组（（装配人为空）、陈恩念）—— 统计里照样算，只是不在导出文件里`，
导出的 Excel/CSV 表头里同样带着这一行 —— 拿到文件的人有权知道少了什么。

> 实测：取消陈恩念（125 条）→ 导出 1194 条（1319 − 125），
> 而屏幕上这一组仍然是 125 条、总记录仍是 1424 条、校验页仍是 38 组 0 漏。
> 导出的 CSV 数据行恰好 1194 行，第一列里 0 次出现「陈恩念」。

### 导出：图片 / PDF / Excel / CSV

结果页底部四个按钮，**导出的数字和屏幕上是同一个来源**（`S.last` 存的就是本次渲染用的结果对象，
不是重新算一遍），所以不会出现「屏幕 12 套、导出 13 套」。

| 格式 | 实现方式 | 说明 |
|---|---|---|
| **图片 `.png`**（首选） | **直接用 canvas 画**，不截屏、不依赖 CSS | 发微信群、贴车间最方便。跟当前视图走：在「明细表/交叉表」导出的就是表格图，在「排行图」导出的就是柱状图。2 倍图，微信压缩后仍然清楚 |
| **PDF** | `window.print()` + 专用打印样式 | **不自造 PDF** —— 无依赖环境里嵌中文字体做不好，自己生成的很容易变方块。走系统打印对话框选「另存为 PDF」，中文完美，也随时能打纸质版 |
| **Excel `.xlsx`** | **按 OOXML 手工拼 ZIP**（store 无压缩，不装任何第三方库） | 两个工作表：**汇总**（当前视图，交叉表就导交叉表）+ **明细**（全部行，不受屏上 200 行限制）。带表头底色、数字格式 `0` / `0.0`、自动筛选、列宽 |
| **CSV** | UTF-8 + BOM | 给别的系统导数据用 |

> 没做 Word。工厂里没人拿 Word 看统计表，要编辑基本都用 Excel ——
> 多一个格式只是多点错的机会。真需要的话加起来也很快。

图片是 canvas 现画的，专门处理了两件容易出丑陋结果的事：
- **表头的对齐要跟数字一致** —— 数字右对齐但表头左对齐时，数字会被推到离表头很远的右边，
  看不出是哪一列。现在按「这列含不含数字」统一右对齐。
- **别把富余宽度平摊给所有列** —— 每列最多加 36px，剩下的把整张表居中，列就不会被拉得很空。

图片最多画 120 行，超了在页脚写明「仅显示前 120 行，完整数据请导出 Excel」——
不让人发出去一张自己都没意识到不完整的数据。

导出的每份文件开头都有 **7 行元信息**，这是为了表格转发出去以后别人能看懂：

```
生产计划表 · 月份 → 装配人 统计
数据源：2026年生产计划表) - 副本.xlsx → 生产计划表（命中 646 行）
统计口径：按【月份 → 装配人】分组；时间轴 = 装配完成时间（月份）
统计指标：装配套数、装配数量、按时完工率(%)
筛选条件：装配人=成凌平；装配开始时间 在 2026-09-01 ~ 2026-09-30
一格多人：拆开各算一次
明细范围：只看 装配人 = 成凌平
导出时间：2026-09-22 14:31
```

打印样式专门处理过：导航、按钮、其它三个页面全部隐藏，只留「结果」页；
表格 `thead` 设为 `table-header-group` 会**每页重复表头**，
`tr` 设 `break-inside: avoid` 防止一行被切成两页；延期标红也保留（`print-color-adjust: exact`）。

### 表间联动：已取消

以前会拿 `订单编号` 把两张主力表自动接起来（“这套模具做到哪一步了”）。
现在**每张表自己算自己的**，不做关联 —— 43 张表硬要找关系，用户猜不出来工具在干嘛。
真要看「过了交期还在做」，直接在**总计划表**里筛日期就行。

## 五、电脑 + 手机怎么分工

**核心判断：手机不适合读 62MB 的 xlsx。**

所以不是「同一个界面缩一缩」，而是**两个角色**：

| | Windows 电脑 | 手机 |
|---|---|---|
| 定位 | **完整能力** | **看 + 转发** |
| 导入大文件 | ✅ | ❌（会等很久） |
| 建统计/存模板 | ✅ | 简单筛选 |
| 跑校验 | ✅ | 只看结论 |
| 看结果 | ✅ | ✅ |
| 导出图片发微信 | — | ✅ |
| 打开方式 | 双击 exe / 本地网页 | 扫码打开电脑端生成的报表 |

原型里在窄屏顶部有一条黄色提示条明确说明这一点 —— 避免用户在手机上试了 30 秒以为工具坏了。

## 八、怎么用

### 电脑上（最常用）

双击 `web/index.html`。选文件 → 选 sheet → 设条件 → 跑统计 → 导出。

### 手机上

**在厂里（同一个局域网）**——手机和电脑连同一个 WiFi，电脑上执行：

```
node tools/serve-lan.js
```

会打印出形如 `http://192.168.x.x:8080/` 的地址，手机浏览器直接打开。

**人在外面**——公网地址（不用 VPN）：

```
https://robothjc.github.io/mold-stats/
```

#### ⚠ 手机上的关键一条：别用微信内置浏览器打开

微信 / QQ / 钉钉 / 支付宝这些**内置浏览器基本不允许网页选文件**（安全限制，不是页面坏了）。
症状就是：点了那个虚线框**完全没反应**，或者只能选到图片。

正确做法：点右上角 **···** → **在浏览器打开**（Safari / Chrome / 系统浏览器）。

文件怎么弄到手机上（选一个）：

| 办法 | 步骤 |
|---|---|
| 微信/QQ 发给自己 | 手机上**长按那个文件** → 保存到手机（存到「下载」）→ 浏览器里选 |
| 数据线 | 拷到手机「下载」目录 → 浏览器里选 |
| 网盘 | 下载到本地 → 浏览器里选 |

> 想让微信里**直接**能选文件，技术上要接微信 JS-SDK 的 `wx.chooseMessageFile`，
> 而它需要公众号 appid + 服务端算签名 —— 纯静态页面做不到，得上后端。
> 所以「在浏览器打开」是目前唯一不花成本的路。

## 九、数据安全：真实 Excel 不会被上传

- 仓库里**没有任何** `.xlsx` / `.xls` / `.csv`（`.gitignore` 挡着，`node tools/check-deploy.js` 会核验），仓库体积 **0.00 MB**
- 发布出去的网站就是一个 **~140 KB 的程序**，里面不含任何业务数据
- 同事打开网页时，浏览器把程序下载到本地，然后**在他自己的手机上读取他选的那个文件**。文件从头到尾没离开过设备，也不经过任何服务器 —— 对工厂数据来说这才是应有的姿态
- 首次打开看到的那份示例数据是**合成的**，真实客户名已用 `tools/anonymize.js` 全部替换成化名
- **应用没有写文件的能力**：代码里没有任何 `showSaveFilePicker` / `createWritable` /
  `FileSystemFileHandle`，「原表核对」也是纯读。导出走 Blob 下载，另存为的是新文件。
  「手动删掉某一条」只改内存里的一次统计，不改原表

然后 `node tools/check-deploy.js` 确认线上确实是新的。

### 版本号与缓存（每次改完必做）

**改这个文件之后，一定要把 `web/index.html` 里的 `APP_VER` 加一。** 为什么：

- 整个应用是**一个 HTML 文件**，没有文件名哈希、没有 `?v=` 外链可挂 —— 浏览器缓存了什么，
  肉眼完全看不出来。已经出现过两次「改完测试通过，但浏览器拿的还是上一版」的假象，
  其中一次的表现是 `ReferenceError: renderNeeds is not defined`，看着像代码写错了，
  其实只是读了旧副本
- `APP_VER` 会显示在右上角（`v1.24`）。**换行号对不上之前，先看这个号对不对**
- 页面还会**自己把自己再抓一遍**（`fetch(location.href, {cache:'no-store'})`），
  正则找出线上那一份的 `APP_VER` 做比对；不一致就在顶部弹一条黄条
  `检测到线上是新版本 v1.22，你手上这份是旧缓存 → [立即刷新]`，
  点了会跳到 `?v=1.22`，绕开缓存
- 同时加了 `Cache-Control / Pragma / Expires` 三个 no-cache meta；
  `tools/serve-lan.js` 对局域网也发的是 `Cache-Control: no-store`

> 手机上加了书签、或者微信里存着页面的同事，是最容易撞上缓存的。
> 看不到新功能时：**电脑上 Ctrl+F5，手机上关掉标签页重开**。
